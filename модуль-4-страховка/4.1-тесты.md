# Урок 4.1. Агент пишет тесты — вы читаете

## Зачем это нужно

Без тестов каждая следующая правка — рулетка: исправил одно, сломал неизвестно что, узнал через неделю. Тесты записывают поведение приложения как контракт: если поведение нарушено — тест падает, и вы узнаёте об этом за секунды, а не от пользователя. Для агента тесты — удобный жанр: результат проверяется формально. Именно поэтому фальшивый тест опаснее фальшивого кода: зелёный цвет у честного и у бесполезного теста выглядит одинаково. Читать и провоцировать тесты обязаны вы.

## Что мы делаем

Выписываем 5–7 ожидаемых поведений «Пикселя», просим агента поставить Vitest, вынести логику питомца в отдельный модуль `src/petLogic.js` и написать по списку тесты, затем запускаем и проверяем, что каждый тест понятен и что он действительно может упасть.

## Шаг 1. Составьте список поведений

Тест проверяет не код, а поведение. Напишите 5–7 пунктов по тому, что у вас уже есть, — например: «кормление повышает сытость на 10», «сытость не может превысить 100», «настроение не может уйти ниже 0», «раз в минуту обе шкалы уменьшаются на 1», «если сытость меньше 20 — питомец грустит». Пункт «приложение работает» — не поведение, а пожелание: он не проверяется.

Сначала верните приложение к базовому поведению: спад −1 в минуту (если в 2.3 или 4.2 вы временно его ускоряли — уберите ускорение) — и решите, что делать с расширениями из практик (третья шкала, кнопка сброса): покрывать их тестами или убрать.

## Шаг 2. Попросите тесты по списку

Промпт ниже. Пусть агент сначала покажет, что собирается установить. Логику питомца (кормление, спад, границы, эмоцию) обязательно вынесите в отдельный модуль — например, `src/petLogic.js`: тесты будут проверять именно его, а не React-компонент, и не потребуют ни браузерной среды, ни лишних пакетов. Если логика уже лежит в отдельном файле (агент мог вынести её раньше) — используйте его, второй создавать не нужно; важно, чтобы тесты проверяли чистый модуль, а не компонент. Чистая функция — такая, чей результат зависит только от аргументов, без скрытой памяти и побочных эффектов; её легко проверять: дал вход — сверил выход. Вынос — нормальный рефакторинг, но он должен быть виден в diff, и поведение приложения не должно измениться.

## Шаг 3. Прочитайте тесты и проверьте их честность

Откройте файл с тестами. Для каждого теста ответьте: какое поведение из списка он проверяет? Затем устройте провокацию: временно сломайте одну функцию руками (не агентом) — например, в `src/petLogic.js` найдите функцию кормления и замените `10` на `1`, сохраните файл (Ctrl+S) и запустите тесты. Хотя бы один тест обязан упасть. Если всё зелёное при сломанной логике — тесты фальшивые, вернитесь к шагу 2. Верните функцию на место.

## Prompt

```
Установи Vitest как dev-зависимость (сначала покажи команду,
которую выполнишь) и напиши тесты для логики моего
приложения.

Проверь ровно это поведение:
[СПИСОК 5–7 ПОВЕДЕНИЙ]

Требования:
1) вынеси логику питомца в отдельный модуль src/petLogic.js
и пиши тесты только против него; компонент должен
использовать эти функции;
2) тесты должны падать, если поведение нарушено;
3) не пиши тестов, которые проходят всегда;
4) не меняй поведение приложения ради прохождения тестов;
5) добавь в package.json скрипт "test": "vitest run";
6) после запуска покажи результат всех тестов.
```

**Где живут тесты и как их запускать.** Тесты — в файле `src/petLogic.test.js` рядом с логикой (Vitest сам находит файлы `*.test.js`). Запуск: `npx vitest run` — один прогон и выход; `npx vitest` — режим наблюдения, сам перезапускает тесты при изменениях (терминал при этом занят, это не «зависло»; для выхода нажмите `q`); после пункта 5 из промпта хватит `npm test`. Команду запуска вы должны знать наизусть — это часть чеклиста. Vitest — dev-зависимость: пакет, который нужен только для разработки и тестов, а не для работы приложения.

## Что может пойти не так

1. **Вечнозелёные тесты.** Тест, который проходит всегда, — например, проверяет, что функция существует, или сравнивает результат с самим собой. Почему: агент оптимизирует под «тесты зелёные», а не под «тесты честные» — запрет в промпте есть, но он может срезать углы. Ловится только провокацией из шага 3.
2. **Агент «чинит» логику под тесты.** Вместо того чтобы тест проверял поведение, агент подгоняет поведение под тест (например, меняет +10 на +5, потому что тест написан про +5). Почему: для модели нет разницы между «сделать тест зелёным» и «сделать поведение правильным». Diff на этом уроке смотреть обязательно: правки логики — красный флаг.

## Как проверить результат

- [ ] Vitest установлен; тесты запускаете вы (`npx vitest run` или `npm test`).
- [ ] Каждый тест соответствует пункту из вашего списка.
- [ ] Логика вынесена в `src/petLogic.js`, компонент её использует, поведение приложения не изменилось.
- [ ] Провокация: сломанная функция роняет минимум один тест.
- [ ] После восстановления функции все тесты зелёные, есть git-коммит.

## Практика

Добавьте новую эмоцию: «объелся» — отдельный эмодзи при сытости ровно 100. Напишите тест на это поведение самостоятельно (у агента можно спросить синтаксис, но не решение), затем попросите агента реализовать так, чтобы тест прошёл. Задание без готового решения: критерий — тест падал до реализации и проходит после.

Два решения, которые придётся принять самому:

- **приоритет.** При сытости 100 и настроении выше 80 подходят сразу два правила — «счастливый» и «объелся». Определитесь, какое важнее, и скажите это агенту; иначе выбор сделают за вас;
- **место.** Тест можно дописать в конец существующего `src/petLogic.test.js` — так его точно увидят. Каркас для ориентира: `test('объелся при сытости 100', () => { expect(getEmotion({ satiety: 100, mood: 50 })).toBe('🤢'); });` — имя функции, параметры и эмодзи подставьте свои, подсмотрев соседние тесты.

## Главное

1. Тест — это записанное поведение, а не записанный код.
2. Логика в отдельном модуле — условие простых тестов: React-компонент проверять заметно сложнее.
3. Тест, который не может упасть, — не тест.
4. Провокация сломанной функцией — единственная проверка честности тестов.
5. Правки логики под тесты — сигнал тревоги, смотрите diff.
6. Запускать тесты должны уметь вы, а не только агент.
