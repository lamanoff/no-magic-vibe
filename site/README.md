# Сайт курса «Vibe Coding без магии»

Статический сайт курса: те же уроки, что лежат в папках `модуль-N-…`, только
в виде страниц с навигацией, чеклистами и сохраняемым прогрессом.
Собирается из markdown — исходники уроков остаются единственным источником правды.

## Что где лежит

| Путь | Что это |
|---|---|
| `../README.md`, `../модуль-*/**.md` | исходники курса: их правим, их же читают студенты |
| `build.mjs` | сборка: markdown → HTML в `../docs/` |
| `serve.mjs` | локальный превью-сервер (нужен только для разработки) |
| `src/course.mjs` | список модулей и уроков, описания схем |
| `src/render.mjs` | markdown → секции → страницы |
| `src/styles.css` | оформление целиком |
| `src/app.js` | прогресс, чеклисты, копирование промптов |
| `src/pixel.mjs` | пиксельный пиксель-питомец: фавиконка и логотип |
| `public/fonts/` | woff2-подмножества шрифтов (кириллица + латиница) |
| `../docs/` | **результат сборки**: именно эту папку отдаёт GitHub Pages |

## Сборка и превью

```bash
cd site
npm install        # один раз: нужен только markdown-it
npm run build      # собрать сайт в ../docs
npm run serve      # открыть http://localhost:5173
npm run dev        # сборка + превью одной командой
```

Сборка затирает `docs/` целиком, поэтому в этой папке ничего не правим руками.

## Как добавить или изменить урок

1. Правим markdown в папке модуля.
2. Если добавился новый урок — дописываем его в `src/course.mjs` (модуль, номер,
   `slug` для имени файла, короткая подпись для боковой панели).
3. `npm run build`.

Разделы внутри урока распознаются по заголовкам второго уровня: «Зачем это нужно»,
«Что мы делаем», «Шаг N», «Prompt», «Что может пойти не так», «Как проверить
результат», «Практика», «Главное». Каждый получает своё оформление. Пункты
`- [ ]` в разделе проверки превращаются в настоящие чекбоксы, по ним и считается
прогресс: урок пройден, когда отмечены все пункты.

### Схемы

Блоки ```mermaid не отдаются в mermaid.js: для каждой схемы в `src/course.mjs`
описано своё представление (маршрут, дерево выбора или поток шагов), которое
рисуется обычным HTML. В описании есть поле `expect` — отрывок исходной схемы.
Если текст схемы в уроке изменится, сборка упадёт с подсказкой: это сделано
специально, чтобы схема на сайте не разошлась с текстом курса незаметно.

## Шрифты

Всё лежит локально, никаких обращений к CDN:

- **Handjet** — заголовки (пиксельный, есть кириллица);
- **PT Sans** — основной текст;
- **IBM Plex Mono** — код, подписи, служебные надписи.

У каждого файла прописан `unicode-range`, поэтому кириллица и латиница берутся
из своих подмножеств, а не подменяются системным шрифтом. Перекачать шрифты:
`npm run fonts`.

## Публикация на GitHub Pages (бесплатно)

Готовый сайт уже лежит в `docs/`, поэтому хостингу не нужна сборка на его стороне.

```bash
# из корня папки курса, где лежат README.md и папка модуля
git init
git add .
git commit -m "Курс и сайт курса"
git branch -M main
git remote add origin https://github.com/<ваш-логин>/vibe-coding-course.git
git push -u origin main
```

Дальше в репозитории: **Settings → Pages → Source: Deploy from a branch →
Branch: `main`, папка `/docs` → Save**. Через минуту сайт откроется по адресу
`https://<ваш-логин>.github.io/vibe-coding-course/`.

Файл `docs/.nojekyll` уже на месте — он отключает обработку через Jekyll.

**После каждой правки уроков** не забываем пересобрать сайт и отправить изменения:

```bash
cd site && npm run build
cd ..
git add . && git commit -m "обновил урок N" && git push
```

Альтернатива: собирать сайт в GitHub Actions и публиковать артефакт — тогда
`docs/` в репозитории хранить не нужно. Для этого курса выбран более простой путь:
в репозитории лежит уже собранный сайт, и Pages отдаёт его как есть.

## Что стоит положить в .gitignore

`site/node_modules/` — он уже прописан в `.gitignore` в корне курса.
Сами шрифты в `site/public/fonts/` коммитим: без них сайт потеряет вид.
