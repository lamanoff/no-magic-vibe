# Урок 2.2. Данные: питомец начинает помнить

## Зачем это нужно

Сейчас счётчики живут в памяти вкладки: перезагрузили страницу — питомец «забыл», что его покормили. Настоящее приложение отличается от демо именно этим: оно сохраняет состояние. Плюс здесь вы впервые учитесь давать агенту правку без переписывания файла целиком — половина багов новичков от того, что агент «переписал начисто» и по дороге потерял работающую функцию.

## Что мы делаем

Добавляем сохранение состояния питомца в `localStorage`: показатели переживают перезагрузку страницы. В курсе это вторая задача плана (если ваша нумерация другая — важна суть, а не номер).

## Шаг 1. Сформулируйте поведение, прежде чем просить код

Правило «как проверить» из урока 1.2 пригождается: что значит «сохранение работает»? Конкретно: покормил → сытость выросла → перезагрузил страницу → сытость осталась. Если не можете сформулировать проверку — вы не готовы просить код.

Четыре факта о `localStorage`, без которых нельзя читать код агента:

- хранит только строки — объекты прогоняют через `JSON.stringify` и `JSON.parse`;
- объём — порядка 5 МБ на сайт;
- данные видны любому в DevTools и живут до очистки хранилища браузера;
- запись может завершиться ошибкой (переполнение, ограничения браузера) — надёжный код это переживает.

## Шаг 2. Попросите точечные изменения

Промпт ниже. Ключевое требование — «покажи, что удалить и что добавить, не переписывай файл целиком». Если инструмент показывает diff — посмотрите его до принятия; если нет — сравните после правки (`git diff`): не потерялось ли что-то из работающего. Правка, которая касается половины файла, — красный флаг: остановитесь и спросите, почему нельзя меньше.

## Шаг 3. Проверьте цикл сохранения и зафиксируйте версию

Проверьте: изменили показатель → перезагрузили → значение на месте. Загляните внутрь хранилища: F12 → вкладка Application → Local Storage → адрес приложения — там лежит состояние питомца (имя ключа выбирал агент). Посмотрите, что внутри, и **запишите имя ключа**: оно понадобится в уроке 2.3, где вы будете менять значения руками. Затем закоммитьте рабочую версию:

```
git add .
git commit -m "сохранение состояния в localStorage"
```

С этого урока заканчивать урок без коммита — плохая привычка: рабочая версия всегда должна существовать в git, а не только на диске.

## Что может пойти не так

1. **Переписал файл и потерял работающее.** Агент «для надёжности» выдаёт весь `App.jsx` заново, и в новой версии пропадает то, что вы добавляли в практике прошлого урока. Почему: модели проще перегенерировать файл, чем аккуратно встроить изменение. Лечится требованием diff и тем, что рабочая версия уже в git — любую потерю видно в `git diff`.
2. **Сохраняет не то, что нужно.** Например, кладёт объект без сериализации (в хранилище попадает `[object Object]`) или записывает значение, прочитанное до изменения, — и после перезагрузки вы видите старое число. Почему: агент не видит приложение в действии, он работает с кодом как с текстом. Проверяйте цикл «изменил → перезагрузил → значение на месте» минимум дважды, со вторым показателем.

## Как проверить результат

- [ ] Клик «покормить» → сытость выросла.
- [ ] Перезагрузка страницы → сытость на месте.
- [ ] То же для настроения.
- [ ] Обе кнопки работают, как до правки.
- [ ] В git есть коммит с рабочей версией.
- [ ] Diff правки касается только сохранения, а не всего файла.

## Практика

Добавьте кнопку «начать заново», которая сбрасывает показатели к стартовым значениям. Без готового решения. Требования: точечные изменения, существующее не сломать, после правки — проверка полного цикла: покормил → перезагрузил → сбросил → перезагрузил. Если после сброса что-то «возрождается» из `localStorage` — вы нашли баг и уже знаете, что с ним делать.

Кнопку можно оставить — она пригодится. Только помните: в уроке 2.3 у сброса появится вторая обязанность (сбрасывать и отметку времени), а в 4.1 логика сброса попадёт под тесты.

## Главное

1. Сохранение — граница между демо и настоящим приложением.
2. Сначала сформулируйте проверку, потом просите код.
3. Переписывание файла целиком — главный источник потерянных фич.
4. Git-коммит рабочей версии — обязательное завершение каждого урока.
5. Цикл «изменил → перезагрузил → значение на месте» — ваша личная проверка: минимум дважды и на обеих шкалах.
