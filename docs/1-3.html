Зачем это нужно

#

Агент умеет запускать команды — и умеет ошибаться в них: не та ОС, не та версия Node, лишние пакеты «на всякий случай». Этот урок нужен не чтобы настроить проект (это минуты), а чтобы вы видели, какие команды выполняет агент, и могли повторить их сами. Если проект ляжет завтра, перезапускать его будете вы, а не агент.

»

Что мы делаем

#

Создаём проект React + Vite в отдельной папке, переносим внутрь документы из уроков 1.1–1.2, делаем первый git-коммит, ставим зависимости, запускаем dev-сервер и открываем пустое приложение в браузере. Это просто шаблон Vite — но уже первый работающий артефакт под контролем версий.

Про путь к папке. Работайте в пути без пробелов и нелатинских букв и, если можете, вне облачных папок (OneDrive, Dropbox): синхронизация конфликтует с node_modules и git, а путь с пробелами приходится каждый раз брать в кавычки. Если папка уже создана с пробелами — не страшно, просто помните про кавычки в командах.

1

Шаг 1. Проверьте Node.js

#

Выполните в терминале node -v. Нужна актуальная LTS-версия (точное требование зависит от версии Vite — если версия старая, ошибку вы увидите при установке, и её надо показать агенту, а не угадывать). Если Node нет — поставьте его с официального сайта nodejs.org, выбрав LTS. После установки полностью закройте и заново откройте VS Code: уже открытый терминал новую команду не увидит, и вы решите, что установка не удалась.

2

Шаг 2. Попросите агента создать проект

#

Откройте терминал в папке курса (не внутри будущей папки проекта) — в VS Code это Ctrl+— и убедитесь, что он открылся именно там: командаcdбез аргументов в Windows покажет текущую папку. Если терминал оказался в другом месте, откройте папку заново (File → Open Folder) или перейдите в неё командойcd "полный путь"` (путь с пробелами — в кавычках). Затем отправьте агенту промпт ниже. Важно: агент сначала показывает план команд и ждёт вашего «да», а подтверждение команд в вашем инструменте должно быть включено — это правило всего курса.

3

Шаг 3. Перенесите документы, сделайте первый коммит и перезапустите сервер сами

#

  1. Убедитесь, что проект создан: в папке курса появилась папка pixel-pet.

  2. Перенесите docs из папки курса внутрь pixel-pet — проще всего перетащить папку в проводнике VS Code. Затем откройте в редакторе именно pixel-pet (File → Open Folder): с этого момента агент должен работать только из корня проекта, иначе он видит лишнюю папку курса и путается в путях.

  3. Сделайте первый git-коммит. Коммит — это снимок файлов, к которому можно вернуться:

    команды терминала
    cd pixel-pet
git init
git add .
git commit -m "стартовый шаблон Vite + документы"

    git init выполняется один раз на проект; дальше перед каждым коммитом — только git add . и git commit -m "...". Папка node_modules в коммит не попадёт: в шаблоне Vite уже есть .gitignore.

  4. Остановите сервер (Ctrl+C в терминале, где он запущен) и запустите заново сами: npm run dev — эта команда записана в package.json в поле scripts. Если терминал новый, сначала перейдите в папку проекта (cd pixel-pet); если вы уже в ней — cd не нужен.

    Что такое dev-сервер: локальный веб-сервер, который отдаёт приложение по адресу вида http://localhost:5173 и сам пересобирает его при изменениях. Пока он запущен, вкладку с приложением можно просто обновлять. Если без агента не получилось — урок не пройден: вернитесь к шагу 2 и заставьте агента объяснить каждую команду.

Промпт для агента 
В этой папке создай новый проект React + Vite (JavaScript,
без TypeScript) с именем pixel-pet.

Сначала выведи список команд, которые собираешься выполнить,
и дождись моего подтверждения. Затем:
1) создай проект;
2) установи зависимости;
3) запусти dev-сервер и напиши, по какому адресу открылось
приложение, а также перечисли команды запуска и остановки
так, чтобы я мог повторить их без тебя.

Не устанавливай ничего сверх стандартного шаблона.
!

Что может пойти не так

#
  1. Команды для чужой системы или устаревшие флаги. Агент генерирует команды из памяти, а не из вашего терминала: названия пакетов и флаги меняются от версии к версии. Поэтому «сначала покажи команды» — не формальность: читайте, что он собрался выполнять.
  2. Лишние установки. «Давай сразу поставим роутер, стейт-менеджер и линтер» — частая инициатива. Каждый лишний пакет — код, который вы не понимаете, и ошибки, которые не сможете объяснить. В первой версии проекта — только шаблон.
  3. Агент молчит и ждёт. Команда создания проекта может задавать вопрос в терминале — тогда агент не «завис», а ждёт вашего ответа. Если непонятно, чего он ждёт, попросите показать выполняемую команду и выполните её сами, отвечая на вопросы: вам нужна цель, а не исполнитель.
✓

Как проверить результат

#
✎

Практика

#

Остановите dev-сервер (Ctrl+C) — на Windows занятые файлы из node_modules не удалятся. Затем удалите папку node_modules (без агента) и выполните npm install — ровно это же делал агент в шаге 2. Минутное упражнение, которое снимает страх «я сломал проект». Если после этого сервер не запускается — у вас есть текст ошибки, и вы уже знаете, кому его показать и в каком формате (подробно — в уроке 3.1).

★

Главное

#
  1. Команды агента вы видите до выполнения — иначе это чёрный ящик, а не агент.
  2. Агент помнит команды, но не знает вашу систему: проверяйте перед запуском.
  3. Умение перезапустить сервер самому — часть результата этого урока.
  4. После урока в проекте должен быть только стандартный шаблон.
  5. Ошибка при установке — данные для агента, а не повод всё переделывать.
